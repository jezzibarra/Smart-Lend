# PROJECT AUDIT REPORT

**Project:** Smart Lending Application (SLAP)
**Stack (actual):** Node.js / Express 5, MongoDB (Mongoose), vanilla HTML/CSS/JS (not Next.js/Tailwind as described in the request)
**Audit date:** 2026-11-09
**Scope:** Full codebase audit (backend, database, auth, frontend, tests, scripts)

---

## 1. Existing Working Features

- Unified Express backend (`server.js`) delegating from `Admin/server.js` and `Login/server.js`.
- MongoDB connection with retries and credential-free logging (`config/db.js`).
- JWT (HS256) authentication with 1-hour expiry (`config/security.js`).
- Role-based access control (`middleware/auth.js`): `authenticate`, `requireAdmin`, `requireCustomer`.
- Customer signup with OTP verification (hashed OTP, single-use, attempt-limited).
- Customer login restricted to `customer` role; admin login restricted to `admin` role.
- Google OAuth sign-in for customers and admins (whitelist for admins).
- Customer profile read/update, own loans, own payments, own applications.
- Admin client (loan) record CRUD with audit logging.
- Admin transaction creation.
- Admin security overview and audit log viewing.
- Borrower evaluation / loan application submission with server-side financial evaluation (`config/lending.js`).
- Application status review workflow with mandatory decision reasons.
- Secure document upload (magic-byte validation, 1.5 MB limit, stored outside web root).
- Authenticated document download with ownership checks.
- Rate limiting (distributed Redis with in-memory fallback).
- Security headers and CSP.
- CORS allowlist (no wildcard with credentials).
- Audit logging without IPs/tokens/passwords.
- Test suites (`test/*.test.js`) and dev seed scripts.

## 2. Broken or Incomplete Features

- Application document download endpoint is referenced by `Dashboard/client.html` but must be verified against the server route; any mismatch breaks document retrieval. (Priority: HIGH)
- `evaluateApplication` client-submitted `evaluation` values are accepted in the payload but ignored server-side (correct), yet the form/API may still display stale client figures. (Priority: MEDIUM)
- Customer profile update pulls several fields directly from `req.body` instead of the allowlisted body, bypassing the allowlist pattern. (Priority: MEDIUM)
- Unused models (`Loan`, `Payment`, `RepaymentSchedule`, `Notification`) have no endpoints; loan/payment management features advertised in the README are not actually implemented. (Priority: HIGH)
- Repayment schedule generators (`generateRepaymentSchedule`, `generateReducingSchedule`) are never invoked by any endpoint. (Priority: HIGH)
- Notification system has a model but no creation/delivery endpoints. (Priority: MEDIUM)

## 3. Missing Essential Features

- Dedicated, repeatable customer test account creation in MongoDB is only available via scripts; no documented `TEST_CREDENTIALS.md` exists yet. (Priority: HIGH)
- No password reset / forgot-password flow. (Priority: MEDIUM)
- No email verification status enforcement beyond signup OTP. (Priority: LOW)
- No pagination on list endpoints (`/api/clients`, `/api/transactions`, audit logs, applications). (Priority: MEDIUM)
- No loan lifecycle management (approve application -> create Loan + RepaymentSchedule). (Priority: HIGH)

## 4. Backend and Database Problems

- Hardcoded secrets/defaults in `server.js`: Google client ID and authorized admin emails fall back to real values, including personal email addresses. (Priority: CRITICAL)
- Rate limiter uses IP-derived keys (`applicationCreateLimiter`, and `ip` policies in login/signup/otp) despite the documented "keyed on identifier, not IP" privacy policy. IP is processed in memory/Redis but never persisted. (Priority: MEDIUM)
- `/api/config` exposes dev test account credentials (acceptable in dev only; must remain disabled in production). (Priority: LOW)
- Duplicate `toPesos`/`roundCentavos` declarations in `config/lending.js`. (Priority: LOW)
- `Notification`, `Loan`, `Payment`, `RepaymentSchedule` models unused -> dead code and schema drift risk. (Priority: MEDIUM)
- No unique index on `User.mobile` although it is required; duplicates possible. (Priority: MEDIUM)
- `Client.clientId`/`Transaction.txnId` generated by counting documents can collide under concurrency. (Priority: MEDIUM)
- Server keeps running (open handle) so test processes hang unless `--test-force-exit` is used. (Priority: LOW)

## 5. Security Vulnerabilities

- Hardcoded authorized admin emails / Google client ID defaults in source code. (Priority: CRITICAL)
- CSP allows `unsafe-inline` for scripts/styles (required by current inline handlers; XSS risk if input reflection occurs). (Priority: MEDIUM)
- OTP is generated with `crypto.randomInt` but delivered via console in dev; acceptable for dev, must never happen in prod (guarded). (Priority: LOW)
- No CSRF protection (mitigated by Bearer token + CORS). (Priority: LOW)
- No account lockout persistence; rate limiter is ephemeral (Redis/memory) and resets. (Priority: MEDIUM)
- `/api/admin/google` auto-provisions admin accounts for any whitelisted email without MFA beyond Google. (Priority: MEDIUM)
- Test mode exposes OTP codes when `SLAP_TEST_MODE=1` (must never be enabled in production). (Priority: HIGH if misconfigured)
- `debug-login.js` and `test-login*.js` exist in repo root and may leak debugging logic. (Priority: LOW)

## 6. UI/UX and Responsiveness Problems

- Heavy reliance on inline `onclick` handlers (requires `unsafe-inline` CSP). (Priority: MEDIUM)
- `Dashboard/client.html` and `Admin/admin.html` are large single-file pages with embedded scripts; maintainability and accessibility concerns. (Priority: LOW)
- No skip-to-content or ARIA landmarks in several pages. (Priority: LOW)
- Mobile sidebar toggle exists but keyboard accessibility is limited. (Priority: LOW)

## 7. Duplicate or Unnecessary Files

- `Admin/package.json`, `Login/package.json` (leftover from old insecure standalone servers). (Priority: LOW)
- `Admin/server.js`, `Login/server.js` (thin wrappers; could be removed if unused, but verify). (Priority: LOW)
- `debug-login.js`, `test-login.js`, `test-login.mjs` (debug/test artifacts in repo root). (Priority: LOW)
- `final-run.log`, `sec-audit.log`, `test-output.txt`, `test-security.txt` (generated artifacts). (Priority: LOW)
- `.kilo/` (agent metadata, not application code). (Priority: LOW)

## 8. Missing Integrations and Dependencies

- SMTP is optional; without it OTP cannot be delivered in production. (Priority: HIGH for prod)
- Redis is optional; rate limiting is per-instance without it. (Priority: MEDIUM)
- No test runner dependency beyond Node built-in; okay.

## 9. Recommended Improvements

- Remove hardcoded defaults for Google client ID and admin emails; fail fast if unset in production.
- Implement Loan/Payment/RepaymentSchedule endpoints or remove unused models.
- Add pagination and consistent error handling.
- Add password reset flow.
- Clean up duplicate/unused files.
- Fix test bug (`api(BASE + ...)` double prefix) so the suite runs.
- Create documented customer test account and `TEST_CREDENTIALS.md`.
- Add `after` hooks / `--test-force-exit` guidance.
